# 한글·学 — 识别型韩语学习（Windows 优先）

对标「识日」产品骨架的韩语版，但按你的决定砍掉了全部输出型题型（拼写 / 手写 / 听写 / 跟读评分），
定位为 **识认 + 听觉 + 语法感知** 工具。

**双击 `启动.bat` 即可运行**，浏览器自动打开。关闭黑窗口即退出。

**线上版：<https://shilnnshue.github.io/krlearn/>** —— 手机也能直接开，见 [一·五](#一五部署到公网免费)。

## 一、启动

```
双击  启动.bat
```

需要本机有 Python 3.10+（已内置路径探测，找不到会提示）。

- 服务只监听 `127.0.0.1`，不对外暴露，不联网（音频全部预先合成在本地）。
- **固定用 8765 端口**。进度存在浏览器 `localStorage` 里，而 `localStorage` 按「域名 + 端口」
  隔离，端口一变进度就像全丢了。所以重复双击**不会**开第二个，只会把浏览器指回原来那个。
- 只有 8765 被别的程序占了才会顺延，这时窗口里会明确提示「换个端口等于换个存档位置」。

> 直接双击 `index.html` 不行——浏览器会拦 `file://` 下的 JSON 请求。必须走 `启动.bat`。

### 打不开的时候

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 窗口一闪就没 | bat 的换行/编码坏了（早期版本是 LF 换行，`if (...)` 块会解析失败） | 现在这份是 GBK + CRLF + `chcp 936`，正常不会 |
| 提示找不到 Python | PATH 里没有，或命中的是微软商店的假 python | 装官方 Python 3.10+，安装时勾 Add to PATH |
| 窗口里中文乱码 | 控制台代码页被改过，或外部注入了 `PYTHONUTF8` | bat 已自行 `chcp 936` 并清掉这两个变量，正常不会出现 |
| 浏览器没自动打开 | 默认浏览器没注册 | 手动访问窗口里打印的 `http://127.0.0.1:8765/index.html` |
| 提示端口被占 | 8765 被别的程序用着 | 窗口会给出新端口；也可 `set KR_PORT=8800` 后手动跑 `python serve.py` |

异常退出时窗口会停住等你按回车，不闪退 —— 把那段报错整段发我就行。

## 一·五、部署到公网（免费）

**已经上线了：<https://shilnnshue.github.io/krlearn/>**（GitHub Pages，仓库 `shilnnshue/krlearn`）

这是**临时可用的第二条路**：仓库是 public，开 Pages 就不用另注册账号，50 秒构建完成。
代价是国内访问一般（github.io 时常被 DNS 污染），且微信里打不开。正式对外还是建议
GitHub + Cloudflare Pages，全免费、不用备案，完整步骤见 **[`DEPLOY.md`](DEPLOY.md)**。

GitHub Pages 有两个额外注意点：

- 根目录必须有 **`.nojekyll`**（已加），否则 Jekyll 会跳过 `_headers` 这类下划线开头的文件，
  而且会去逐个处理那 1.6 万个文件
- 站点总大小软上限 **1GB**、带宽 100GB/月；现在是 292MB，约 3.4 万次完整访问就吃满
  （实际一条音频才 15KB 上下，够测试用）

换成 Cloudflare Pages 时要记住两个硬约束：

- **Cloudflare Pages 免费版上限 20,000 个文件**，现在用了 16,265 个（音频占 16,219），余量约 3,700。
  每加一个词会新增 **19 个文件**（词 1 + 例句 3 + 变位 15），也就是**再加约 195 个词就撞墙**。
  **拆 R2 的一整套已经备好了**（`DEPLOY.md` 第六节）：`tools/upload_r2.py` 增量上传（断了可续），
  页面这边只改 `index.html` 里 `window.KR_AUDIO_BASE` 一行，再给 Pages 加一条
  `rm -rf audio` 构建命令。拆完 Pages 上只剩 40 来个文件，词库加到一万词也不受限。
  留空不填时行为与原来完全一致，所以不拆也能照常部署。
- **国内 + 微信是绕不过去的坎**。免费海外平台在国内都能打开，但速度中等；
  **微信内置浏览器会拦截未备案域名**，点了显示「已停止访问该网页」。
  要真正在微信里传播，只有「买域名 → 备案 → 走 EdgeOne 国内节点」一条路。
  测试阶段让朋友「复制链接到浏览器打开」即可。

## 二、已经能用的功能

### 三种学习模式

| 模式 | 流程 | 适合 |
|---|---|---|
| **纯背** | 韩文 → 翻面看释义和两条例句 → 「下一个」一路翻下去，**完全不出题** | 想先把词过一遍 |
| **经典** | 翻面 → 「认识，测一下」进四选一 / 连连看验证；「不认识」直接降级 | 想要记得牢 |
| **快速** | 词义同屏自评 | 通勤碎片时间 |

首页主按钮「开始背词」按设置里的模式走；三个快捷入口可以直接指定模式。
纯背模式翻到背面就算学会（写入 SRS，明天进「等待复习」），不打分也不出题。

**答题页右上角有个「经典 / 快速」小胶囊**，点一下当场换模式，不用退出重进
（纯背和词汇测试不显示——那两个模式没有可切的余地）。

### 学习闭环
- **卡片**：韩文 → 轻点翻面 → 释义 / 词性 / TOPIK / 全部例句（超出屏幕可上下滚）
- **手势**：双击任意位置发音 · 长按复制韩文 · 正面单击翻面
- **自动朗读**：设置里两个独立开关 ——「自动读单词」翻到释义面时念一遍，
  「自动读例句」接着把例句逐条念完（单词 → 例句1 → 例句2 → 例句3，句间留 300ms）。
  朗读中的那一句会高亮；手动点任何喇叭会立刻打断队列。
  **翻到下一张卡、退出学习、切换页面，都会当场掐断正在响的那一条**（不只是清队列）——
  以前只清队列，当前那条会一直念到结尾，换个页面还在响。
- **例句整框可点**：不用精准点到小喇叭，点框里任何位置都出声
- **复习流**：到期词自动出题，5 种题型随机 —— 四选一（韩→中）/ 四选一（中→韩）/ 听音选义 / **连连看** / 变位选择
- **连连看**：当前词 + 3 个同词性干扰词打乱成左右两列，一组组配对；四组全配完才结算，
  过程中任何一组配错就判「没记住」（短间隔重来），全对才升间隔
- **FSRS 记忆调度**：`ts-fsrs` 官方实现（UMD 内联，零构建），四档评分收敛为「对→Good / 错→Again」
- **错题集**：答错自动入库，答对扣减，清零后自动移出
- **生词本**：卡片背面 / 词条页可收藏
- **笔记**：卡片背面「＋记笔记」，按词存储
- **每日上限**：默认 20 词，防止复习雪崩
- **已掌握**：词条页一键标记，标记后彻底退出学习与复习队列；首页「其他 → 已掌握」可一键移回
- **复习债务缓解**：长按首页「等待复习」卡片 0.7 秒，把今天到期的词整体顺延到明天（进度不丢）

### 韩语字母（重做过，不是「五十音」照搬）
- 19 辅音 + 21 元音 + 28 收音，全部可点听
- **音节构建器**：初声 × 中声 × 终声自由组合，实时显示合成音节
- **音节表**：19×21 = 399 个无收音音节，点击发声
- 每个字母带发音说明（如 ㄹ「元音前近 r，收音时近 l」）

### 语法（67 条）

首页「常用 → 语法」进入。按 **接续 → 意思 → 怎么用 → 例句 → 易错点** 组织，
不是把语法点列成一张表就完事。

- **67 条**：初级 40 / 中级 27，覆盖 TOPIK 1–4 高频语法
- 每条都给到：**接续方式**（动词/形容词/名词分别怎么接）、一句话意思、用法说明、
  **3 条例句**（韩 + 中）、**易错点**，以及和相似语法的区别
- **列表页**能按等级筛选，能搜韩文或中文 —— 搜「想要」和搜「고 싶다」都能找到 `-고 싶다`
- 详情页底部有上一条 / 下一条，可以当顺读材料；返回列表时筛选和搜索词都保留
- **例句有配音**：201 条全部预生成在 `audio/grammar/ex/`，整条框可点、正在念的句子会高亮，
  和词条例句是同一套播放器（手动点喇叭会打断自动朗读，翻页即静音）

**易错点是真的易错点**，不是套话：

- `-는 바람에` 后面必须接不好的结果，`-느라고` 前后主语必须一致
- `-밖에 없다` 后面必须是否定谓语，否则整句错
- `-자마자` 前面不能用过去时（도착했자마자 ✗）
- 있다/없다 的现在定语用 `-는`：없는 사람（不是 없는→없은）
- 形容词的定语形是 `-(으)ㄴ`（예쁜 옷），动词现在时才是 `-는`（읽는 책）—— 最容易混的一块

数据在 `data/grammar.json`，由 `tools/build_grammar.py` 生成（生成时校验字段、
标点、韩中配对、id 重复）。要加条目改脚本里的 `G` 列表，重跑 `python tools/build_grammar.py`。
`tools/check_data.py` 也会一并校验语法数据，`tools/check_grammar.js` 做交互回归。

> **语法形态本身不配音**。67 条里有 31 条带 `-아/어요`、`-(으)ㄹ 거예요` 这类标注符号，
> 直接丢给 TTS 会念成「아 슬래시 어요」，比不念更糟；只念 201 条干净例句。

## 三、技术选型（和原 Prompt 的差异，重要）

| 环节 | 原 Prompt 方案 | 实际采用 | 原因 |
|---|---|---|---|
| 韩语发音 | Naver CLOVA Voice | **edge-tts（ko-KR-SunHiNeural）** | CLOVA 要 NAVER Cloud 企业账号，国内独立开发者基本申请不下来；edge-tts 免费、无需 key、韩语音色质量够用。全部**预生成**（16219 条），运行时不联网 |
| 动词变位 | `@dongsa/conjugation` | **自写规则引擎**（`tools/conjugate.py`） | 外部库返回 39 种形式需再筛选映射，且不规则类型判断不可靠。自写按「词库标注不规则类型 + 规则合并」实现，**75 条断言全通过**（见脚本内 `CASES`） |
| SRS | `ts-fsrs` | `ts-fsrs` ✅ 一致 | 直接内联 UMD 构建，零构建 |
| 客户端 | RN / Flutter | **原生 JS 单页 + 本地 http 服务** | Windows 优先，这样零安装、零构建、改一行刷新即生效；核心逻辑后续可直接搬进 Tauri 出 exe |
| 语法解析 | DeepSeek 预生成 | **未做** | 需要 API key 和例句全量跑一遍，属于二期 |

原 Prompt 里「CLOVA 错误率 0.3% / Azure 1.8%」这组数字我无法核实，别写进对外材料。

### ⚠️ 加词前必读：音频为什么会「张冠李戴」

音频文件名是词条 id（`w0316.mp3`），而 id 是**按数组顺序编的**。任何一次往词库里
插入词条，后面的 id 全部重排，旧 mp3 就被顶到别的词头上 —— 文件名对、内容错。

这个问题在扩库时踩过两次（459 条错位 + 一批例句截断）。现在的防线有三道：

1. **指纹清单** `data/audio_manifest.json`：记录「路径 → 文本 md5」。生成脚本的
   跳过条件从「文件存在」改成「文件存在**且**指纹对得上」。文本变了就自动重生成。
2. **`audit_audio.py`**：用「字节数 ≈ a×音节数+b」回归粗筛可疑项，再逐条重新合成做
   字节比对（edge-tts 对同文本输出稳定）。只查可疑的，1 万多条几轮就能收敛。
3. **`--stale` 模式**：按 mtime 找出「数据改过、音频没跟上」的条目。

改完词库的固定动作：

```bat
python tools\audit_audio.py --stale --dry    :: 先看有多少条要查
python tools\audit_audio.py --stale          :: 逐条比对并修（会更新 mtime，重跑即收敛）
```

> 变位音频的文件名是 `00.mp3`–`14.mp3`（**从 0 开始**），前端 `URLS.conj(id, i)` 的
> `i` 也是 0-based。改成 1-based 会把第 N 行的音频覆盖到第 N+1 行上 —— 这是踩过的坑，
> 写校验脚本时务必对齐。

`irregular` 字段取值：`none` / `하` / `ㅂ` / `ㄷ` / `ㅅ` / `ㅎ` / `르` / `으` / `ㄹ` / `ㅜ`。
**标错会导致变位错误**，加词时对照 `conjugate.py` 里的 `CASES` 自测用例确认（当前 138 条断言全通过）。

想扩中级词，直接在 `tools/topik2_words.py` 的 `NEW` 里按同样格式追加
（韩文, 中文, 词性, 不规则类型, [(韩, 中, 等级) × 3]），再跑上面四条命令即可。

> 例句是我人工写的，语法按标准韩语处理，但没有经过母语者逐句校对。
> 如果要做正式产品，建议找韩语母语者过一遍 —— 特别是 3 级（长句）那部分。
